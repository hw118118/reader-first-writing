# 文种改变哪些编辑决定

下列是选材线索。遵守约定俗成的表格、单位模板和法定用语。一个交付物兼有两种目的时，根据阅读场合决定先后，保留必要的交叉引用。

| 使用场合 | 优先展开 | 容易误删或多写的内容 |
|---|---|---|
| 上会决策、申请资源 | 要决定的事、建议、代价、会改变建议的条件 | 推荐试点时保留样本局限。只有确实存在的备选才值得比较 |
| 产品或技术评审 | 用一个真实或标为假设的输入说明可见行为，再沿关键路径解释机制 | 标出已实现与拟议行为。流程图中的动作要能在接口或文字中找到；限制写在受影响的行为旁 |
| 调研、实验报告 | 问题、观察结果、证据怎样得到、能推到多远 | 比较须说明口径、样本和反例。无法判断因果就交代替代解释 |
| 操作手册、交接 | 从操作者看到的状态进入，按执行顺序写动作和可观察结果 | 出错时告诉人何时停、怎样恢复；只需查一个参数时直接给定义、单位和默认值 |
| 教程、科普 | 用读者已知的东西提出问题，带读者完成一个例子，再解释规律 | 新术语在首次使用处解释。类比在哪失效会影响理解时，写出边界 |
| 事故通报、复盘 | 通报先说受影响的人怎样处置；复盘重建影响、时序和原因 | 分开已证实的原因和待查项。处置动作要有负责人和核验方法，缺负责人就保留待定 |
| 项目进度、对外通知 | 进度稿说变化、影响和所需决定；通知说谁在何时要做什么 | 保留日期、渠道、例外。读者用不到的内部协作过程可删 |
| 特写、演讲、个人文章 | 用作者确有的观察、具体场景或有分量的一句话进入，按作者的关注点展开 | 当事人引语须有来源。没有素材就以事实叙述，保留作者节奏 |

例如设计稿写“提交完成后清理旧记录”。若“完成”可能分别指请求返回或接收方保存成功，先查证是哪一个。只有材料确认后，才能改成“接收方保存成功后，发送方才删除旧记录”。材料尚未说明时，要指出这个歧义。把一句话改得更顺，并不能替设计者作决定。
